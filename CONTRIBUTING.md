# Contributing to frameprism

## Contribution workflow

Create a branch, make the focused change, run `make check`, and open a pull
request. Report vulnerabilities through the private channel in
`.github/SECURITY.md`, not a public issue. Tests that require real camera
footage or footage-derived artifacts may be run by maintainers because those
inputs are not distributed.

## Build

The lossless encoder links libjpeg-turbo (the TurboJPEG API) via
`tool/build.rs`. **The default build links the COMMITTED patched
prefix** `deps/.jpeg-prefix` (libjpeg-turbo 3.2.1, built from the
pinned source + `deps/libjpeg-percomp-lossless.patch` — committed with
the repo), so on macOS (the gate toolchain) a bare `cargo build` IS
the contract build with zero setup:

```sh
cd tool
cargo build --release                 # links deps/.jpeg-prefix — zero setup on macOS (the gate toolchain)
```

The prefix is resolved from the manifest dir
(`<tool>/../deps/.jpeg-prefix`); the committed bytes are identical
everywhere, but the prefix is a Darwin (AppleClang) build — the
contract build is macOS-only (on other hosts a link failure is
expected and named). A missing or unresolvable prefix
(no `lib/` + `include/`, or the `libturbojpeg.a`/`libjpeg.a` static
libs absent) is a **NAMED build refusal** at build time, before any
encode — build.rs never silently falls back to another location.

- **`JPEG_TURBO_PREFIX` = the EXPLICIT opt-in** to a different prefix
  (a rebuilt prefix, Homebrew, …); a non-empty value always wins. The
  opt-in is VISIBLE: the report's build-fact line names the prefix
  that was linked. `JPEG_TURBO_PREFIX=/opt/homebrew/opt/jpeg-turbo`
  (the unpatched Homebrew formula) is the **NAMED non-contract path** —
  it silently emits the merged-DHT output, which is why it is never
  the default:

  ```sh
  # non-contract (named) build:
  JPEG_TURBO_PREFIX=/opt/homebrew/opt/jpeg-turbo cargo build --release
  # rebuild the committed prefix from the pinned source (only needed if
  # the committed prefix is absent on this checkout):
  deps/fetch.sh && deps/build-libjpeg.sh   # → deps/.jpeg-prefix
  ```

- **The silent-fallback trap (now closed for bare builds):** an
  unpatched libjpeg resets the DC table numbers in
  `jpeg_default_colorspace()` and forces the SOS DC selector to 0 when
  Ss ≠ 0 (`jcmarker.c` `emit_sos`), so it can only emit the single
  merged-DHT lossless output. The result is **conforming JPEG but NOT
  NLE-compatible — and nothing fails loudly at encode time.** The
  default build can no longer hit this: it links
  the patched prefix, and a broken prefix is a named refusal at build
  time; only an explicit `JPEG_TURBO_PREFIX` opt-in reaches the
  unpatched path. The patched prefix carries the per-component lossless
  DHT fix (`deps/libjpeg-percomp-lossless.patch`, applied to a
  throwaway copy by `deps/build-libjpeg.sh`; the committed source tree
  stays clean). The public build contract and committed pin checks document
  this mechanism.
- **Engine seam:** the default lossless entropy encoder is the native
  Rust T.81 (SOF3) encoder — byte-identical to the libjpeg FFI path on
  every gate. `FRAMEPRISM_ENGINE=ffi|libjpeg|legacy` restores the audited
  FFI engine (any other value is native — the engines are
  byte-identical, so a mis-set var cannot change output bytes). The
  patched prefix is still required: build.rs links libjpeg-turbo, and
  the FFI engine + the lossy path use it (decode/verify is pure Rust).
- The fetched reference source (libjpeg-turbo, the DNG SDK, LibRaw,
  libtiff, tinydng) is gitignored reference material, re-fetchable with
  `deps/fetch.sh` — see `deps/README.md`.

## Verifying without footage

`bash ci/check.sh` IS the CI job — the self-contained, clone-ready gate:

- **`ci/check.sh`** — the single entrypoint that checks the repo
  against its own data: version pins (the byte-identity contracts) →
  the fixture-provenance step (the 12 committed oracle source fixtures
  regenerated byte-identically by the committed deterministic
  generator, `ci/fixture-templates/generate_fixtures.py` — the
  fixtures' provenance authority) → release build + the suite gate
  (`cargo test --release --lib`, the pinned test count) → the
  10-frame synthetic byte-identity oracle (67,762,584 B) from the
  committed `ci/oracle10/` fixture → the 10/8-bit JXL oracle (via
  `ci/check-108.sh`). Any failure is a named FAIL + rc=1 — no silent
  skips anywhere.
- **`ci/check-pins.sh`** — version-pin assertions over `ci/pins.tsv`:
  the cjxl/djxl pin (version **and** sha256 — the byte-identity pin; the
  probed binary is the committed `deps/pinned-binaries/` pair unless
  overridden), zstd, tar, fstool (the in-process lock-grep rows — the
  committed `tool/Cargo.lock` is the single source), and the tool version (the
  `tool/Cargo.toml` grep). The script does not fetch these inputs; a missing
  binary is a named FAIL; every FAIL named, rc=1.
- **`ci/check-108.sh`** — the 10/8-bit JXL oracle (the byte-identity
  gate for `--codec jxl` at 10/8-bit): two committed deterministic
  synthetic source frames (`ci/oracle108/src/`: f10 = UHD 3856×2170
  10-bit; f8 = FHD 1936×1090 8-bit) are re-encoded with the committed
  binary at e7 and every output byte-compared against the committed
  gold (8 `.jxl` planes + the 2 sidecars; the 2,380,943 B
  byte-identity contract).
- **`ci/verify-192f.sh`** — the 962-file sha256 integrity sweep over the
  retained 192f encode set (j92 128+64 DNG, jxl 512+256 `.jxl` +
  sidecar; `ci/manifest-192f.tsv` carries per-file set/relpath/size/
  sha256). Read-only over its inputs; its default set roots are the
  maintainer's local evidence dirs — pass your own `ROOT ...` args for
  a fetched set. Not part of the clone-ready gate.

On macOS (the gate toolchain) the oracle fixtures run with **zero external setup**: the pinned cjxl/
djxl encoder pair (v0.12.0 `1cad73c` — the byte contract for the entire
jxl tier + oracle108) is **committed** in `deps/pinned-binaries/`, and
`ci/pins.tsv` pins both the version and the sha256 of those exact
bytes, so the pin is self-contained (a version drift would silently
change archive bytes).

## Make surface

The ship gate is also exposed as a thin make surface: the `Makefile`
at the repo root. The Makefile carries **no gate logic** — every
target is a thin dispatch to an existing `ci/*.sh` sub-script (with
`--repo`) or a bare `cargo` command from `tool/`; the single source of
gate truth stays `ci/check.sh` (and its sub-scripts).

```sh
make check        # the full ship gate — exactly `bash ci/check.sh` (the default goal)
make help         # the target summary

# the granular targets (1:1 onto the existing gate surface):
make pins         # ci/check-pins.sh   — the version pins
make build        # cargo build --release (from tool/)
make test         # cargo test --release --lib (from tool/)
make clippy       # cargo clippy --workspace -- -D warnings (from tool/)
make oracle108    # ci/check-108.sh    — the 10/8-bit JXL oracle
make xcheck       # ci/check-xcheck.sh — the JXL independent-decoder cross-check
make audit        # ci/check-audit.sh  — the offline dependency audit
make fuzz         # ci/check-fuzz.sh   — the C-boundary fuzz corpus
```

`make check` IS `bash ci/check.sh` — the same gate, the same verdicts
(no suite counts, no byte totals, no assertions in the Makefile — the
gate logic lives in the scripts). The inline `ci/check.sh` steps with
no sub-script (the README doc-drift gate, the 10-frame oracle) have no
make target.

## Test corpus

The corpus is a **registry model**: `testdata/clips.tsv` records the
canonical clip list and `testdata/manifest.tsv` records encode results.
Real camera footage and footage-derived outputs are not distributed. See
`testdata/README.md` for the layout, naming rules, and clip intake protocol.
The **clone-ready sample** is the committed synthetic oracle fixture:
`ci/oracle10/src/` (10 tracked frames — the encode inputs for the
byte-identity arbiters).

## tools/ — research scripts

Python research tools (pure stdlib):

- `dump_dng.py` — minimal DNG/TIFF frame inspector: per-file
  endianness, IFD0 tag table (named where known), sub-IFDs, raw strip
  geometry, XMP/cDNG tags, and per-plane statistics.
- `ljpeg_decode.py` — minimal lossless-JPEG (SOF3, ITU-T T.81)
  reference decoder: decode a tile and verify it against the known
  mosaic (the PSV, component layout, point transform).
- `measure_psv_map.py` — measures the corpus per-tile
  (PSV, orientation) map across all frames of all lossless presets (the
  3-candidate hypothesis check; header-only reads, up to SOS).
- `order_probe.py` — probes the sample order libjpeg-turbo wrote for
  2-component lossless (SOF3): per-MCU interleave vs per-row/per-frame
  block orders, exact-match counts.
- `nle_decode_oracle.py` — the NLE decode oracle
  (sequence protocol): import a DNG folder as a sequence clip, build a
  timeline, seek through frames, parse `ResolveDebug.txt` for decode
  failures inside the probe folder.
- `dct12_dng_probe.py` — measures the dct12 tile structure (full JPEG
  marker sequence + DQT tables, SOF fields, DHT tables, SOS fields, the
  DNG tag plan, per-tile byte counts).
- `dct12_tile_scan.py` — the two-scan baseline-DCT reference decoder for
  the dct12 (tag-7, 12-bit) format — reconstructs the odd rows
  rawpy/LibRaw silently drop.
- `test_vts_parity.py` — parity regression test: `dct12_tile_scan.py`
  vs the production reference decoder (bit-exact on the fixtures).

## Public evidence

Private camera footage and footage-derived measurement artifacts are not
distributed. Public reproducibility rests on the committed synthetic fixtures,
registries, scripts, and gate outputs. The public interface of the tool is the
`--help` surface and `docs/`.
